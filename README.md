# 🛠️ 実務未経験からのWeb・Python開発学習記録

IT業界の実務経験は一切ございません。高校・専門学校で培ったPCスキルやWebデザインの基礎をベースに、2026年5月より本業の傍らで、PythonおよびRuby on Railsを用いたWebアプリケーション・自動化プログラムの独学開発を開始いたしました。

過去にWebデザインの基礎を学んだ経験があり、これまで接客業や物流業などの現場職に従事してきました。現在はライフステージの変化を機に、現場の課題を解決するシステムの構築を目指してプログラミング学習に着手しています。

開発環境には、13年前のPC（Lenovo G580）にメモリ増強とSSD換装を施したLinux環境を使用しています。限られた時間の中で、インフラやハードウェアの制約を技術的代替案で打開し、「動く成果物」をゼロから設計・実装することに注力しています。

## ⚡ 開発実績・リポジトリ一覧

### 1. [python-practice](https://github.com/tosane932/python-practice) - 【Python / Excel】
* **概要**: 大手ニュースサイトを対象とした、データ抽出および蓄積の技術検証プログラム。
* **解決した課題・実装内容**: WAFやIPブロック等のセキュリティ制約を回避するため、RSSフィードを活用した安定的なデータ取得ルートへ方針を最適化。抽出したデータをExcelへ自動保存・追記し、データの重複を常時監視・排除する重複防止ロジックを実装。
* **公開記事**: [「車載ローカルサーバー構想を損切りし、Webアプリケーション開発へ舵を切った判断理由」](https://qiita.com/tosane932/items/37c9d2c482a6611d2f25)

### 2. [puoppo_app](https://github.com/tosane932/puoppo_app) - 【Python / SQLite3 / AI連携】
* **概要**: 前作のスクレイピングロジックを発展させ、バックエンドデータベースと連携させた自動要約Webアプリケーション。
* **解決した課題・実装内容**: データの永続化と処理高速化のため、テキストファイル管理からSQLite3を用いたリレーショナルデータベース管理へと移行。RSSフィードから抽出したデータを自動で抽出し、結果を出力する軽量なバックエンドシステムを10時間の集中開発でスクラッチから構築。
* **公開記事**: [​「無理に近道するより整備された道を行け」物流の教訓からスクレイピングを捨て、公式RSS×Geminiで割り切ったAIアプリを作った話](https://qiita.com/tosane932/items/92bcf28cd91d645596bd)

### 3. [sales_data_app](https://github.com/tosane932/sales_data_app) - 【Python / Flask / PostgreSQL / Docker / google-genai】
* **概要**: 日次の販売数量をデータベースで一元管理し、売上動向の可視化とAI経営コンサルティングを融合させた現場主義のWebアプリケーション。
* **解決した課題・実装内容**: `openpyxl`によるExcel集計ロジックおよびデッドコード（約200行）をすべて削除し、リレーショナルデータベース（PostgreSQL）を用いた堅牢なシステムへ完全移行。`Flask-SQLAlchemy`を導入し集計処理をDB側へ委譲。`google-genai`SDKを使用した非同期AI連携や、環境変数（`config.py`）による安全管理の強化を実装。
* **公開記事**: [「🚛学習100時間のトラックドライバーが、自分のFlaskコードの積載ミスを9つ発見して全部直した話📦」](https://qiita.com/tosane932/items/ac18b633c8c87b9807bb)

### 4. [rails_practice](https://github.com/tosane932/rails_practice) - 【Ruby / Rails 8 / SQLite3 / Render】
* **概要**: より大規模な開発に対応すべく「Ruby on Rails 8」を採用し、インフラ制約の打開を検証した統合Webアプリケーション。
* **解決した課題・実装内容**: クラウドインフラ（Render無料枠）のメモリ不足（OOM）に対する『ローカル・プリコンパイル』の導入、およびサーバー再起動でデータが消失する制約に対するSQLite3データベースの永続ディレクトリ（`storage/`）バインドによるデータ永続化を達成。
* **公開記事**: [「Render無料枠の制限（512MB RAM・Read-only）を回避したRails 8のデプロイ検証」](https://qiita.com/tosane932/items/58e00fc7353ef76b4a62)

### 5. [hiroshima-logistics-hub](https://github.com/tosane932/hiroshima-logistics-hub) - 【Python / JSON / GitHub Pages】
* **概要**: 物流運行管理に必要な外部環境データ（気象・燃料価格・道路情報）を、メインサイトの負荷をかけずに高速供給する「データ出荷型」Webポータル。
* **解決した課題・実装内容**: 画面表示時の動的スクレイピングによる通信ラグを解消するため、Pythonスクリプトによる「定時ハント＆data.json出荷」方式を採用。Pythonバックエンドを持たず、GitHub Pages等での配信を想定した超軽量・高速なフロントエンド構成を実現。

### 6. [driver-personality-test](https://github.com/tosane932/driver-personality-test) - 【JavaScript / HTML / CSS】
* **概要**: 7年7ヶ月のドライバー経験に基づく「現場の危険予知」を診断ツール化した、ブラウザ完結型Webアプリケーション。
